# 복잡한 질의의 라우팅 검증

`routing-cases.yaml`은 금융 업무, 서비스 장애, Acme 반품, 기본 도움 워크플로를 **동시에 후보로 제공**하고, 실제 모델이 질의에 맞는 트리와 실행 단계를 고르는지 확인하는 19개 사례다. 단순 키워드 일치뿐 아니라 서로 다른 가지의 조합, 비슷한 업무의 구분, 명시적으로 제외한 단계, 애매한 요청의 되묻기를 확인한다.

## 실행

저장소 루트에서, ChatGPT에 로그인된 ClawWorks 설정과 인증 프로필을 사용한다. 별도의 검증 설치를 사용한다면 해당 설치의 `OPENCLAW_HOME`과 `OPENCLAW_STATE_DIR`을 지정한다. 인증 정보는 결과에 넣지 않는다.

```sh
node --import tsx scripts/enterprise-routing-eval.ts \
  --model openai/gpt-5.5 \
  --repeat 3 \
  --out ../openclaw-documents/1008-routing/results.json
```

실제 모델을 호출하므로 모델 사용량이 발생한다. `--repeat`는 1~10이며 기본값은 3이다. `--cases`로 다른 사례 파일을 지정할 수 있다. 트리 파일 경로는 저장소 루트 기준이다. 결과 파일은 실행마다 덮어쓰므로 비교 실행에는 다른 출력 이름을 사용한다. 한 건이라도 기대값과 다르면 종료 코드 1을 반환한다.

## 확인할 요청과 경로

| 사례 | 질의의 핵심                                | 기대 동작                                            |
| ---- | ------------------------------------------ | ---------------------------------------------------- |
| 01   | 금융 코드의 TypeScript 리팩터링 설명       | 금융 업무가 아닌 기본 도움 트리 선택                 |
| 02   | 배송 상태만 조회                           | 주문 조회만 선택                                     |
| 03   | 반품 기간 정책만 설명                      | 정책 확인만 선택                                     |
| 04   | 배송일과 정책을 대조해 반품 가능 여부 판단 | 정책 → 주문 조회 → 판단                              |
| 05   | 의심거래보고서의 서술 초안만 작성          | SAR 초안 단계, 제출 제외                             |
| 06   | 이미 작성된 SAR 제출                       | 감독기관 제출 단계, 초안 작성 제외                   |
| 07   | 분기 보고 수치와 누락 항목만 집계          | 보고 준비 단계, 제출 제외                            |
| 08   | “SAR-42 좀 처리해줘”                       | 준비와 제출 중 무엇인지 되묻기                       |
| 09   | 계좌 거래 패턴 검토 + 경영진 현황 요약     | 거래 검토와 경영 보고 가지를 함께 선택               |
| 10   | 신규 고객 위험등급 산정                    | 고객 위험평가 선택, 대출 심사·계좌 개설 제외         |
| 11   | 보험 보장 여부 + 지급 권한 확인            | 보장 확인과 지급 권한 단계만 선택                    |
| 12   | 장애 시 고객 안내 주기 정책                | 안내 정책만 선택, 내부 기록 열람 제외                |
| 13   | 장애 우선순위 계산 + 고객 안내 초안        | 장애 분류와 안내 초안 가지 선택, 상태 변경·전송 제외 |
| 14   | 11번 요청을 영어로 표현                    | 한국어와 같은 경로                                   |
| 15   | 존재하지 않는 주문의 배송 조회 요청        | 주문 조회 경로 선택                                  |
| 16   | 주문·정책 조회를 금지하면서 반품 판단 요구 | 제한과 필요한 정보에 대해 되묻기                     |
| 17   | “보험 청구 CL-42 건 좀 진행해줘”           | 어떤 청구 업무인지 되묻기                            |
| 18   | “서비스 장애 INC-42 관련해서 처리해줘”     | 어떤 장애 업무인지 되묻기                            |
| 19   | SAR 초안·사전 확인 완료, 이제 제출 요청    | 명시적인 제출 의도는 실행 경로로 선택                |

질의 원문과 정확한 노드 ID는 YAML에 있다. 업무 사례는 루트·중간 단계·선택한 끝 단계를 모두 포함한 `expected.steps`의 **전체 목록과 순서**를 비교한다. 선택한 노드의 조상은 먼저 실행되지만 자손은 자동 선택되지 않는다. 여러 분기의 공통 조상은 한 번만 실행된다. 부모만 선택한 경로와 자식까지 선택한 경로는 다르다. 모델이 업무 트리 불일치(`treeId: null`)를 답해 기본 도움 트리로 연결되는 경우도 기본 도움 트리의 정상 선택으로 판정한다. 원래 선택 방식은 결과의 `source`에 남긴다. 01번은 도메인 혼동 여부만 평가하며, 별도 지침이 없는 기본 도움 트리의 세부 단계는 고정하지 않는다.

## 결과 해석과 검증 범위

결과 JSON에는 질의, 사전 기대값, 모델이 선택한 트리·단계, 선택 이유 또는 되묻는 질문, 판정, 걸린 시간, 입력 파일과 주요 소스의 SHA-256을 저장한다. 호출마다 저장하므로 중단 전 결과도 남는다. 모델 호출 실패나 유효하지 않은 경로는 업무 실행을 시작하지 않고 차단되며 통과로 인정하지 않는다.

시간은 각 요청의 라우터 호출 시작부터 경로 선택 반환까지 측정한다. 모델 준비와 네트워크 대기가 포함된다. 첫 호출과 이후 호출을 구분하고, 정확도와 중앙값·95백분위 시간을 함께 확인한다. 작은 고정 사례 모음이므로 운영 환경의 전체 정확도나 동시 처리 성능을 보장하지 않는다.

**이 실행기는 경로 선택만 검증한다.** 업무용 MCP, KB 검색, 실제 지급·제출, 최종 사용자 답변, GUI는 실행하지 않는다. 특히 15번은 “없는 주문이라고 올바르게 답했는지”를 증명하지 않는다. 그런 검증은 `MANUAL_MATRIX.ko.md`와 튜토리얼의 실제 서비스 환경에서 별도로 진행한다.

GUI에서 같은 질의를 시험하려면 각 예제의 설치·가져오기 안내에 따라 필요한 트리와 서비스를 준비한 다음, 사례마다 새 채팅을 열어 질의 원문을 입력한다. 선택된 트리·실행 단계와 실제 호출 내역·최종 답변을 함께 확인하고 캡처한다. 제출·지급 요청은 테스트 데이터와 테스트 서비스에서만 재현한다. 이 문서 자체는 해당 GUI 시험의 완료 증거가 아니다.
